## 1. 最终采用的候选流程

归档原图 → GroundingDINO Base联合查询fire/smoke → 按类筛分数及NMS → 上游火烟YOLO补充候选 → 同类空间去重、DINO框优先 → 保存新版本 → 人工复核 → 人工通过后导出YOLO标签。

## 2. 选样、评价与实际调参过程

全部200幅来自已经完成A/B独立标注的原冻结任务，原划分均为train。独立test未参与选参、训练或指标验证；批量阶段仅为现有划分中的图像生成待复核候选，正式test真值仍须独立人工协议确认。A和B分别作为参考，不选较有利的一套当唯一真值。

按同类、置信度降序、IoU≥0.50一对一匹配，计算TP/FP/FN、Precision、Recall、F1和分类别指标；不计算缺少低阈值完整候选的AP。模型输出仍待人工复核。

1. 以种子271027冻结40幅调参图和40幅复验图，均按无目标、仅fire、仅smoke、fire+smoke四层各10幅选样；两批的已知采集组不重叠。
2. Tiny阶段比较联合fire/smoke、flame/smoke及包含cloud、sun、lamp、fog、reflection的背景类别查询。比较按类阈值、背景得分差、640与800短边，并检查既有YOLO的补充作用。每个参数组合多为对同一次真实输出离线重筛，不是重复做全部模型前向。
3. 第一组联合方案在调参40幅上改善，锁定后在分组40幅复验中丢失更多真实目标，未发布。
4. DINO与YOLO融合在40幅上改善；另以种子271028冻结27幅新图，与前80幅不同、且与调参图的已知采集组不重叠。该批出现室内薄烟漏检，局部门槛未通过。薄烟Q103是真实待复核案例，不能因为新候选为空就判作正常。
5. 测试保留受联合结果支持的原烟雾框，以及允许同一查询输出fire和smoke两类。部分调参值提高，但Tiny融合扩展到200幅时，相对A的总体召回下降，因此未采用Tiny融合进行批量生成。
6. 下载官方Base固定快照，校验7个文件，权重933400872字节。比较原独立提示词、联合简单类别、联合烟羽/背景类别和描述短语/背景类别；固定40幅，比较按类阈值与是否加入辅助YOLO。
7. 从调参结果锁定F1优先与召回优先两个候选，再检查另外160幅。F1优先方案在200幅整体P/R/F1均提高，93幅未参与当前参数选择的图片总体也提高，最终选择其作为新候选版本。

调节过的维度、所有参数组合及失败结果保存在本机`artifacts/prelabel_optimization_20261027/`。代码保存在[scripts/prelabel_tuning](../scripts/prelabel_tuning/README.md)。没有将某一次未奏效的参数选择改写为成功记录。

### 数据与验证局限

- 原200幅先前已参与诊断，本轮也有多轮探索和复验，不能称为从未使用过的独立测试。原A/B标注本身没有被改写。
- 93幅未参与本轮参数选择，但部分与调参图同源；D-FIRE原事件信息不完整，已知组隔离不等于证明所有事件独立。
- 早期门槛要求每个小批、每个类别TP不降、FP不升，并同时要求总体P至少提升5个百分点、F1提升5个百分点及FP减少20%。**这一严格逐子集门槛最终没有全部通过。**
- 本次发布决定依据用户“总体减少误检与漏检”的目标：相同200幅对A/B的P/R/F1和两类汇总均改善，93幅总体也改善。因此只追加待复核候选并保留局部退化，不宣称所有子集优化成功，不将新结果作为自动真值。

误检计数相对A/B分别减少159/166个，漏检减少6/13个。Precision是自动框匹配质量，不是图片分类正确率；A/B分歧、框边界和碎片划分也会影响数值。

最终方案在27幅检查图上相对A/B，TP从9/10变为8/9，局部召回仍下降；相对A在93幅中也存在个别类别退化。完整逐类、逐批结果未删除，见机器报告。因此必须继续人工校验薄烟、小火、强光/云雾等案例。

## 4. 批量结果与历史保护

700幅共生成700个新候选版本，失败0幅。新版本539幅有框、161幅无框，合计fire框528个、smoke框366个。原900条候选保留，正式库累计1600条候选、18次运行。批量处理约238秒，不含模型加载，不是检测页面FPS口径。

来源声明为正常的200幅中，出现候选框的图片从177幅降至73幅。它是来源正常候选上的框出现数量；尚未逐图确认正常真值，不能命名为正式测试误报率。

批量前创建SQLite一致性备份，批量后对旧候选与人工记录、冻结任务和A/B提交核对哈希，均未改变。原400份A/B提交、2条人工作业记录保留，本轮自动批准数为0。195项回归测试、17幅真实适配器复现及浏览器验证通过；实际入库的200幅指标与冻结试验结果逐项一致。

Quality原200幅报告仍对应原冻结Tiny候选，保持30.89%/27.85%等原数值。增强方案对比另存本报告，不能用新结果回填原任务并伪称原始成绩。

## 5. 现在如何继续复核

1. 打开`http://127.0.0.1:8506/Annotations`，填真实复核者，选择“人工复核”。
2. 选择图片和最新“自动增强候选 Base+YOLO（待人工复核）”版本，点击“采用所选预标注”。采用前保存需要保留的未保存画布。
3. 对照原图补漏、删误检、改类和边界；勾选真实处理选项。确认无目标时明确勾选整图无fire/smoke，再保存通过。已有人工通过版本保留，不会因模型重跑自动变化。
4. 先参考本机`artifacts/prelabel_optimization_20261027/batch/优先复核图片.md`中的26幅：A/B均标有某类而增强结果没有该类。这是正常复核的优先顺序，不是新增仲裁或额外一轮重标要求。
5. 另有402幅新旧类别分歧，多数可能是旧误检被移除，不能全部判为错误或要求逐图仲裁。完整分歧保存在同目录`review_priorities.json`，原候选可随时切换查看。

有效复核工时尚未计量，本轮不填写“已节省多少人工工时”。后续可在实际复核中用可暂停计时记录有效查看/修改时间。
