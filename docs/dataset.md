# 数据采集、导入、统计与划分

进入侧边栏 `Dataset` 管理原始素材；随后进入 `Annotations` 使用 [GroundingDINO预标注、人工复核与YOLO导出](annotations.md)，再进入 `Training` [训练模型与单独评估](training.md)。实际数据数量与正式训练实验仍须自行积累并核实。

## 操作顺序

1. 在“导入与采集”新建批次。填写名称、**采集组编号**、来源说明，显式选择自采/公开/演示，声明场景中有fire、smoke、normal或尚未核实unknown，并选室内外、光照、规模、距离、视角。公开素材写数据集、链接及许可说明，自采写日期和设备等记录。内容声明不是逐帧人工标注，不能作为正式准确率的参考标签。
2. 同一原视频、同次拍摄或相互关联场景中的图片/片段使用**相同采集组编号**。一个批次是一组来源/场景声明，一次文件夹导入沿用同一批次；独立拍摄分不同批次/组导入。组号是划分隔离的依据，不是随意递增的文件序号。
3. 多选上传图片或视频后点击“导入上传文件”。也可展开文件夹导入，输入本机绝对路径，选择是否包含子目录。单次文件夹支持1～5000个受支持素材，归档目录本身不会被重复导入。上传随批次切换清空，避免把前一批文件误导入新组。文件逐个校验并显示结果，坏文件不会使整批有效素材丢失。
4. 使用USB采集时先选自采或演示批次，再点击“采集一张截图”或“采集一段短片”；点击后才打开本机摄像头。短片1～30秒、默认5秒，完成/失败均释放设备。采集原始画面，不叠加YOLO检测框；无声H.264短片按实际采集时间重采样为10fps，保留采集时间与设备元数据。最多300个采样画面/64MB临时JPEG，磁盘保留256MB，异常或未完成时不把短片计入数据集。
5. 在“素材与抽帧”查看来源、文件校验值；需要时勾选预览。选择归档视频，使用其已有批次，指定时间间隔（0.1～3600秒）和单次上限（1～2000帧）。逐帧解码、依照视频PTS采样，每帧保存原视频ID、帧号和时间，不从播放器截图，也不把结果框当原始数据。无效时间戳会中止，并保留已导入的实际帧。
6. 在“统计与划分”查看去重数量、抽帧图片、重复来源记录、来源/场景冲突、类别声明与场景覆盖。下载来源CSV及统计JSON，整理题目数据说明。对错误声明须人工核实；批次来源声明与目标框标注分开保存，`Annotations`中的框修改不会倒写批次声明。
7. 至少准备3个互不关联且含图片的正式组，设置比例（默认70/20/10）和种子42，先预览，再保存版本。整组分配会偏离精确比例，尤其样本较少或组大小差异大时；不会拆开同源图像凑比例。

## 计数口径

- 图片先应用EXIF方向并转RGB，归档为PNG；按尺寸与解码像素去重。重命名和无损重编码不增加图片数，有损重压缩造成像素变化则不保证判重。记录原文件SHA-256和归档SHA-256，原输入文件不被修改。
- 视频保留原字节；用ffprobe读取视频流实际解码帧数、尺寸、时长，单文件探测上限120秒。相同字节的视频只计一段、时长只加一次。转码、重叠剪辑和近似画面不自动认定为重复，须通过正确组号及人工检查控制。
- 同一素材可以关联多个来源，但只计一份。重复来源记录指超过唯一素材数的来源关联；同一文件在同批次重复点击导入是幂等操作，不增加来源条数。USB每次实际采集单独保留采集编号与时间，重复内容仍不增加唯一素材数。
- 自采火烟图像500幅、自采火烟视频300段且合计600秒、正常图像200幅、自采占比30%的目标来自第四题。界面显示的是**来源和场景声明下的数量进度**，达数后仍须人工核查场景覆盖、独立性、真实性和标注质量。
- 自采占比按去重图像（含视频抽帧）与原视频条目合计计算，分母排除演示/测试。图像与视频仍分别列数，不把视频帧数量作为视频段数。
- 素材存在演示来源（即使也被声明自采）时，排除正式数量与划分；自采/公开来源冲突不计为自采；正常与火烟场景声明冲突不计入任何火烟/正常达标数。尚未核实的unknown也不计火烟/正常数。
- fire与smoke可同时出现，两类图像数不能相加作为唯一图像总数。帧图像继承原视频的**场景声明**，不意味着每帧实际都有火烟，下一阶段须复核。

## 划分与复现

同一组、父视频/抽帧、重复素材构成关联图，按连通组划分；重复素材跨两个组时会连接这两个组。演示素材本身虽不进入输出列表，也不会被用来切断已存在的组关联。此策略防止已知同源泄漏，不能自动发现被错误分组的转码或近似素材。

保存时重新核对数据指纹、预览分配及每个归档文件SHA-256，阻止保存过时预览或损坏文件引用。版本目录包含：

```text
data/fire_dataset/
  catalog.sqlite3             # 批次、唯一素材、来源关联、划分索引
  media/images/<id>.png
  media/videos/<sha256>.<ext>
  splits/split_<日期_编号>/
    manifest.json             # 比例、种子、实际数量、组关系、完整来源快照
    train.txt
    val.txt
    test.txt
```

列表是以**数据根目录**为基准的图片相对路径。JSON同时记录图片和视频所属集合，原件不移动、不重命名。此处只保存划分，不为未标注素材生成空YOLO标签。`Annotations`复核完成后可按当前划分导出训练目录与data.yaml；必须复核划分内全部图片。

新保存的划分在数据库中记录manifest的SHA-256，训练导出会再次核验。升级前的历史划分仍保留，可继续查看和下载；若没有校验值，需在当前素材清单上重新预览、保存版本后才能用于训练导出，不自动给旧清单补签。

新导入改变指纹时，旧预览禁止保存；旧版本标为历史快照并保持原样，可下载原清单。指纹包括批次与来源信息，所以仅追加来源也会产生新快照状态。关闭服务后可备份完整数据目录，保留数据库、媒体和版本目录一起迁移。

默认根目录是 `data/fire_dataset/`，可用环境变量 `FIRE_DATASET_ROOT` 改位置。数据与个人采集画面已被Git忽略，不会随代码commit/push上传。本阶段没有自动下载外部数据集或把演示素材充作自采数据。

## 验证

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
.\.venv\Scripts\python.exe scripts\verify_dataset.py
```

验证脚本使用独立 `artifacts/dataset_checks/` 目录和合成/公开视频素材，模拟USB截图、真实FFmpeg短片编码及页面操作；本机摄像头只取帧后丢弃，不保存个人画面。结果见 [dataset_verification.json](../reports/dataset_verification.json)，79项单元测试含原报警、媒体和摄像头检查。合成测试中的来源标记用于测试计数逻辑，不是本人的实习自采数据。

浏览器验证先根据报告中的 `browser_root` 设置 `FIRE_DATASET_ROOT`（完整首次验证须使用空目录），设置独立 `FIRE_ALARM_LOG_PATH` 并启动服务。使用本机Playwright/Edge和 `ALARM_APP_URL` 运行 `scripts/verify_dataset_browser.mjs`；同一目录重启服务后加 `--history-only` 验证持久化。重新执行完整验证时先运行Python验证脚本，取得一套新建测试目录。报告为 [dataset_browser.json](../reports/dataset_browser.json)，测试数据和截图仍在忽略目录中。
