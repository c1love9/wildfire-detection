# 报警截图与前后片段

每个首次确认的火烟事件现在会保存一张带框截图，以及默认“确认前5秒、确认后10秒”的静音视频。在 `Alarm History` 选择事件即可查看截图、播放和拖动视频；旧日志仍可正常查询，不会因缺少媒体而报错。

## 操作

1. 按 [quick_start.md](quick_start.md) 启动项目，进入 `Demo Videos`。
2. 展开“报警截图与片段”，保持“保存报警截图和片段”开启；可修改确认前、确认后保存秒数。运行或暂停期间参数锁定，需要先停止再修改。
3. 点击“开始检测”。首次连续确认进入关注级时保存截图并开始收集片段；该时间不是三级红色报警的首次出现时间。之后升级、降级不会给同一事件重复生成片段。
4. 检测继续后，收齐确认后的画面即在后台编码。自然结束、手动停止或检测异常时，将已有画面生成较短片段。暂停不会推进视频时间，也不会凭等待时间补足后置片段。
5. 在 `Alarm History` 中筛选、选择事件，查看截图和视频。生成过程中会显示等待提示，完成后自动刷新；随后可用播放器播放、暂停和拖动。页面同时说明首次确认在片段中的位置。
6. 视频开头、尾部或缓存不足时会标明时间不足，显示实际可用范围。文件被移动或删除时显示提示；可以继续查看其他日志。

例如事件在原视频第7.5秒首次确认，默认目标片段为2.5～17.5秒。如果第0.5秒就确认，则没有5秒的前置画面，片段从视频开头开始，页面会明确说明。

## 配置与依赖

[configs/recording.json](../configs/recording.json) 保存默认值。网页调整用于本次运行；实际参数随事件媒体记录保存。默认开启，前5秒、后10秒，以最多30帧／秒采样，JPEG质量85；前置缓存最多32MiB、300帧，录制与编码中的片段合计最多4个，磁盘至少保留256MiB。单段目标总时长不能超过60秒。

本机已验证 **FFmpeg 8.0.1 / libx264**。新电脑还需安装含libx264的FFmpeg并加入PATH；复验还需要同套安装中的ffprobe。Python依赖版本不变，仓库不附带FFmpeg二进制。安装来源可从 [FFmpeg官方页面](https://ffmpeg.org/download.html) 选择。检查：

```powershell
ffmpeg -version
ffmpeg -hide_banner -encoders | Select-String libx264
ffprobe -version
```

编码器不在PATH时，可在启动服务前设置 `FIRE_ALARM_FFMPEG` 为ffmpeg.exe的完整路径，或在录制配置的 `ffmpeg_binary` 中指定路径。没有编码器时，检测与报警继续、截图仍会保存，页面明确提示片段未生成。

## 文件和日志关联

默认位置：

```text
artifacts/alarms/alarms.sqlite3
artifacts/alarms/media/<事件编号>/snapshot.jpg
artifacts/alarms/media/<事件编号>/clip.mp4
```

数据库新增 `event_media` 表，通过事件编号关联已有事件，保存相对路径、生成状态、确认帧与视频时间、目标／实际范围、截短标记和实际配置。原有事件、等级变化及编号保持不变；旧数据库首次打开会创建新表，原记录不会被删除或改写。

|状态|含义|
|---|---|
|recording|正在收集确认后的画面，截图通常已经可查看。|
|encoding|后台正在生成MP4，页面会自动刷新。|
|ready|前后目标窗口均已满足，可以回放。|
|partial|片段可以回放，但确认前或确认后的可用范围不足。|
|failed|媒体保存或编码失败；若截图已成功，仍可查看截图，页面显示具体原因。|

媒体随日志保存在本机，已由 `artifacts/` 的忽略规则排除，不随commit／push上传。备份时应一起保留数据库与媒体目录；只复制数据库不能恢复视频文件。

设置 `FIRE_ALARM_LOG_PATH` 后，默认媒体目录随数据库放在其旁边的 `media/`；也可以用 `FIRE_ALARM_MEDIA_ROOT` 指定媒体根目录。两者在重启时需保持对应。验证脚本使用独立数据库与媒体目录，不混入正常使用记录。

## 时间与资源处理

缓存保存压缩后的带框画面，以源视频时间戳裁定窗口；不会把界面处理耗时当作素材时间。超过录制帧率时只降低媒体采样率，检测仍逐帧执行。编码按采样帧之间的实际时间间隔组织，再生成30帧／秒的H.264 MP4；必要时重复显示相邻采样画面，保持时间对应。边界受源帧间隔和输出帧周期影响，最后一帧的结束时间在源文件结束／停止时按最后帧间隔估计。源时间戳本身为估计值时，历史页也会说明。

片段为H.264、yuv420p、静音MP4，可在已验证的Edge浏览器播放。采用该编码的原因与Streamlit的 [视频格式说明](https://docs.streamlit.io/1.50.0/develop/api-reference/media/st.video) 一致；帧间隔组织参考 [FFmpeg concat文档](https://ffmpeg.org/ffmpeg-formats.html#concat-1)。截图和片段都沿用当前显示画面的缩放上限，并非原始分辨率视频的无损拷贝。

仅前置压缩缓存受32MiB／300帧限制，该值不代表整个Python或GPU的内存。片段中间帧写入本地临时目录；后台单任务编码，成功或失败后清理已知临时帧。过多重叠事件时，仍保存新事件截图并说明视频队列已满。磁盘不足、文件写入失败或编码失败均会显示提示，不改变报警判定。已保存的最终媒体不自动删除，需自行安排保留空间。

强制终止程序可能留下未完成片段与临时帧，历史页会显示尚未完成，不会把它伪装成可回放视频；请重新检测该素材。正常停止会结束收集并在后台完成已收集内容，停止并不代表火情恢复。

## 复验

```powershell
.\.venv\Scripts\python.exe .\scripts\verify_recording.py
```

脚本实际生成并解码片段、检查编码和时长，然后运行页面检查。产物位于本机 `artifacts/recording_checks/`。真实浏览器检查使用 [verify_recording_browser.mjs](../scripts/verify_recording_browser.mjs)，运行条件与 [报警浏览器检查](alarm.md) 相同；应使用独立的空日志库。重启同一服务／数据库后，传入 `--history-only` 可复查已保存媒体。

实现：[recording.py](../recording.py) 管理有界缓存与片段编码，[video_detection.py](../video_detection.py) 连接视频生命周期，[alarm_log.py](../alarm_log.py) 保存媒体关联，日志页负责显示和回放。
