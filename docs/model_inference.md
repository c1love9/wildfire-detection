# 自训模型接入图片、视频和摄像头

成功训练的best.pt会自动加入对应数据目录的检测模型列表。无需复制到fire-models，也不会覆盖上游权重。图片在 `Home` 检测，视频与本机摄像头在 `Demo Videos` 检测；`Demo Images`仍为原始图片画廊。

## 使用顺序

|步骤|操作|实际行为|
|---|---|---|
|1. 完成训练|在Training使用已复核数据训练，等待任务状态“已完成”|只收录成功训练的best.pt；正在训练、失败、取消、中断及单独评估任务都不作为检测模型|
|2. 图片选择|Home保留Fire Detection类型，在Select Model Size中选择“自训 · 实验说明 · 任务尾号 · best”|显示训练任务、执行者、轮数及权重校验摘要；仍可选fire_n等上游模型，General仍用于COCO通用检测|
|3. 图片检测|选择CPU/GPU和推理图像尺寸，上传图片、选择样例或输入网址|使用所选模型生成带框图和类别计数，可下载结果；切换模型重新推理|
|4. 视频/摄像头选择|Demo Videos选择来源，再在“检测模型”选同一自训任务；检测设置中可调整推理尺寸|图片与视频页的选择相互独立；自训默认采用该任务的训练尺寸，上游默认640|
|5. 开始检测|设置置信度、报警和媒体规则后点击开始|仍使用原有连续帧/区域确认、分级、SQLite日志、截图、前后片段和模拟位置/视角流程|
|6. 切换模型|先停止，再选择其他模型并重新开始|运行和暂停时均锁定模型、尺寸、设备及输入参数；新开始建立新观测与报警状态，不把旧模型的连续命中带入新模型|
|7. 查询历史|Alarm History选择事件，查看“模型与推理参数快照”或导出CSV|看到当时模型来源、训练任务、权重SHA-256、推理尺寸、设备和训练数据指纹；切换不改写历史|

训练“完成”表示计算流程完成，不保证对真实火烟有效；应先查看独立评估。主数据目录当前没有正式自训任务时，列表只显示已有上游模型，完成正式训练后自动出现自训选项。测试脚本的合成模型留在独立artifacts目录，未导入主目录冒充正式成果。

## 切换、校验与日志

模型清单读取当前 `FIRE_DATASET_ROOT`（默认data/fire_dataset），对照Training保存的完成凭据、数据指纹和最佳权重哈希。删除、修改权重或完成凭据后，该自训项仍明确显示不可用及原因，禁止加载；不会悄悄改用上游模型。训练目录与数据库需一起保留，不能只放一个散落的PT文件冒充完成任务。当前不接收网页上传的任意权重，也不从其他数据根目录自动搜集模型。

运行时按路径、SHA-256、设备、尺寸和来源信息缓存最多4个模型，命中缓存前仍校验文件。图片与视频/摄像头共用加锁的推理实现，避免YOLO的可变预测器跨线程或设备混用。运行中的观测固定模型对象与来源快照；即使外部文件之后变化，内存中的观测继续使用已加载的版本，停止后的下一次加载重新校验。

模型必须为仅含fire/smoke的目标检测模型。上游fire_n通常是0=smoke、1=fire，自训导出是0=fire、1=smoke；统计和报警按**类别名称**处理，自训模型额外核验其固定映射，避免序号颠倒。推理固定FP32、最多300框，图像尺寸为64～1280的32倍数。页面提供常用尺寸及当前训练尺寸；尺寸和阈值变化影响结果，做对比时应统一设置。

视频暂停保留原观测、下一帧与报警状态；摄像头暂停释放设备，继续建立新观测段并重新确认，但使用同一固定模型。只有停止后才能换模型。停止、EOF或设备异常仍表示观察结束，不表示火情恢复。

每个视频/摄像头观测的runs.metadata_json新增model快照，保留模型标识、来源、训练任务、数据指纹、权重哈希、实际类别映射、设备、尺寸、FP32及运行库版本；原confidence、nms_iou、weights和位置/视角字段保留。日志表结构不变，旧记录可读；没有记录过的模型来源/哈希/任务留空或标记“旧记录未保存”，不反推填充。CSV增加相应列，原列保留。

推理参数参考 [Ultralytics Predict文档](https://docs.ultralytics.com/modes/predict/)；实现以本项目固定8.3.203版本和本机测试为准，未升级框架或引入新的依赖。

## 验证与复现

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
.\.venv\Scripts\python.exe scripts\verify_model_integration.py
```

124项测试包含此前112项及12项模型清单/缓存/类别映射/篡改/历史兼容检查。Python脚本在独立目录用合成图形及明确标记的模拟复核训练40轮小模型，真实运行CPU/GPU图片推理、40帧视频、连续确认/分级、截图/H.264片段、受控摄像头两个观测段、真实USB摄像头推理/释放/继续，以及页面模型切换和旧General功能。物理摄像头只检测后丢弃，不保存个人画面；带媒体的测试只使用合成素材。结果见 [model_integration.json](../reports/model_integration.json)。

调试页面而无需重复训练时，可将 `MODEL_VERIFY_ROOT` 指向该报告root对应的**绝对artifacts/model_checks验证目录**后重跑脚本，复用其已完成合成模型并新建报警测试日志；不支持用此参数指向主数据目录。

浏览器验证根据报告的dataset_root和alarm_log，设置独立 `FIRE_DATASET_ROOT`、`FIRE_ALARM_LOG_PATH`并启动8502服务。使用本机Playwright/Edge执行 `scripts/verify_model_browser.mjs`（可通过 `PLAYWRIGHT_MODULE`指定模块、`ALARM_APP_URL`指定服务）。验证图片上传/切换、视频上传/切换/暂停/继续/停止、历史模型信息/CSV/截图与回放，以及自训模型在真实摄像头页面的暂停/继续/停止。物理摄像头环节关闭媒体并将报警阈值设为1，不截图；失败截图遮蔽所有图片/视频。

同一独立目录重启服务后，加 `--history-only`核验同一模型仍可选择、旧事件媒体可回放、CSV字节保持一致。报告见 [model_browser.json](../reports/model_browser.json)。模型和媒体仍被Git忽略，只提交代码、说明及验证摘要。

这些结果证明模型能接入系统，不能证明真实火灾精度、误报率或泛化。正式自采数据、双人独立参考标注、正式训练及公平独立测试仍需完成，见 [requirements_audit.md](requirements_audit.md)。
