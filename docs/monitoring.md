# 模拟位置、摄像头视角与历史回溯

依据第四题第4页说明⑥，本阶段使用固定经纬度与手动角度演示，未连接物理GPS/北斗或云台传感器。所有页面、日志和CSV均明确标注“模拟”。

## 使用

1. 进入 `Demo Videos`，按原流程选择内置视频、上传文件或本机摄像头。
2. 打开“监控点位置与视角（模拟）”，位置记录方式默认“模拟定位”。选择演示监控点A或B，可修改经纬度、水平角、俯仰角和水平视场角；无坐标时选择“不记录位置”。预设文件为 `configs/monitoring_points.json`，A/B是可替换的示例坐标，不代表实际设备位置，也不自动切换视频源。
3. 页面下方查看地图。水平角0°向北、90°向东，顺时针增加；俯仰角负值表示向下。蓝色扇形只展示水平朝向与水平视场，图示半径固定100米，俯仰角单独显示，不推算地面覆盖范围。
4. 点击开始后，当前位置与视角绑定本次观测并锁定编辑。报警后地图点位变红；暂停/停止/断流保留最后判定。需要更换点位时先停止。摄像头暂停后继续的新观测段继承同一位置与视角，并重新确认报警。
5. 进入 `Alarm History`，可按来源、等级筛选；地图显示有坐标的匹配事件，选中事件会定位到该事件当时的监控点并显示当时的视角。鼠标悬停点位可看事件/等级/记录时间，平移缩放可查看其他点位。选中的截图和视频仍在下方回放。
6. CSV新增监控点、位置来源、经纬度及角度。老日志或未记录位置的事件显示“未记录”，不套用当前默认点位。

网页编辑仅影响当前浏览器后续观测，不会覆盖配置文件。需要重启后保留个人默认值时编辑预设文件；当前数据库已保存的观测快照不受影响。每个事件通过其观测 `runs.metadata_json.monitoring_point` 关联快照，不需要修改现有数据库表结构。

## 地图与边界

- 地图使用PyDeck和CARTO在线底图，不需要在仓库写入地图密钥。在线底图需要网络，坐标与角度文本始终显示；可取消“显示在线地图底图”，保留点位和方向图层。
- 坐标统一使用WGS84，内部地图顺序为 `[经度, 纬度]`。不混用高德/百度坐标；范围外、NaN等无效参数不能启动带该位置的观测。
- 点位是**摄像头关联的模拟位置**，不是画面中火焰的实测经纬度。当前没有距离、相机标定、地形或目标投影计算，不声称火源定位精度。
- 不把地图扇形或检测框的面积当作燃烧面积；像素掩码与火灾面积曲线尚待实现。
- A/B是位置预设而非完整多路摄像头通道；命名通道与视频源绑定、RTSP等仍待后续阶段。
- 地图刷新和推理分别运行，拖动地图不计入连续确认帧数；地图按约1秒刷新报警颜色，检测仍沿用原有采样时钟。

## 验证

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
.\.venv\Scripts\python.exe scripts\verify_monitoring.py
```

第二项打开本机摄像头检测10帧并释放设备，实拍环节不保存个人图像或日志。公开视频完整294帧与重复公开帧的模拟摄像头输入分别携带A/B点位，验证真实YOLO、报警日志、截图与H.264片段。重复帧与模拟时间仅用于功能检查。

浏览器脚本使用Playwright与本机Edge；设置 `PLAYWRIGHT_MODULE` 指向可用模块，`ALARM_APP_URL` 指向使用测试数据库的服务后运行：

```powershell
node scripts\verify_monitoring_browser.mjs
```

测试数据库路径在 `reports/monitoring_verification.json`，启动测试服务时通过 `FIRE_ALARM_LOG_PATH` 指定；勿把测试记录写入正式日志。结果在 `reports/monitoring_browser.json`，临时图片与数据库在已忽略的 `artifacts/monitoring_checks/`。

重启测试服务并保持相同测试数据库后，可加 `--history-only` 再运行浏览器脚本，覆盖从日志页首次进入、历史媒体回放及进入检测页的顺序。离线地图测试使用独立浏览器环境并屏蔽地图服务；Streamlit 1.50使用内嵌样式URL绘制无远程数据源的背景，避免其默认联网底图和对样式对象的兼容问题。

API参考：[Streamlit 1.50 PyDeck接口](https://docs.streamlit.io/1.50.0/develop/api-reference/charts/st.pydeck_chart)、[PyDeck Deck与地图提供方](https://deckgl.readthedocs.io/en/latest/deck.html)。完整未完成项见 [题目对照表](requirements_audit.md)。
