# 26幅优先复核操作指南

这份清单来自已经完成的200幅A/B独立标注：26幅中，两人都标过某类目标，但2026-10-27增强候选没有该类框。其中18幅重点检查smoke，8幅检查fire。它们是疑似漏检线索，不能只凭清单认定模型或人工一定错。原方案也没检出该类的难例包含在内，不能把26幅全部称为新增退化。

本轮只做Annotations普通人工校验，不重做A/B，不增加逐图仲裁。A/B原始提交、旧候选和已经保存的人工版本继续保留。

## 进入筛选

1. 打开本机服务的 **Annotations** 页面，填写“执行者/复核者姓名或编号”，如本人姓名或固定编号。
2. “标注工作区”选 **人工复核**，“复核范围”选 **优先复核（26幅）**。本机存在清单时默认选中这个范围。
3. “复核图片”现在只列出这26幅，名称带原任务 **Q编号、重点类别、文件名和当前状态**。按顺序做即可；可搜索Q编号或图像ID。
4. 展开“查看优先复核清单和当前状态”可看全表。需要只处理剩余图片时，勾选“只看尚未通过”。草稿也算尚未通过；取消后可回看已通过记录。通过后总清单仍是26幅。

Q编号沿用原200幅任务，并不是26张重新编号。若打开了其他端口或数据目录、没有清单，页面只提供“全部图片”，不会伪造26幅；本机清单放在数据根目录的 `review_lists/priority.json`，随整个数据目录一起备份。

## 每张图按这个顺序做

|顺序|检查与操作|完成标准|
|---|---|---|
|1. 先看整图|看清火焰、烟雾实际位置，再看黄色提示的重点类别。也检查另一类及其他区域，不能只看原有框|知道哪些区域应保留、补框、删框或拿不准|
|2. 检查当前画布|已有人工版本会优先载入；否则载入最新候选。上方“预标注版本”下拉框只是选择候选，点击“采用所选预标注”才会换画布|不能把下拉框显示的候选框数当作当前画布数量；看画布下方“当前画布 N 个框”|
|3. 补漏|点击画布内“画框”，从目标左上角拖到右下角，选中新画的框，再把“框类别”设为fire或smoke|红框=fire，蓝框=smoke。注意检查新框类别，避免修改之前选中的框|
|4. 删误检/重复框|选中对应编号或框，点击“删除选中框”；删错用“撤销”|灯光、反光、云雾等不能仅凭颜色或模型置信度标成火烟；同一目标同一类别避免重复框|
|5. 改类别/范围|点击“选择/移动”，选中目标，拖动框或四角；必要时修改x1、y1、x2、y2原图坐标；类错则修改“框类别”|框尽量贴合可见目标，不把大片背景、灯具或整间房一起包入|
|6. 保存|在“复核处理（可多选）”选实际做过的操作，再点“确认复核通过”|看到保存成功与下方新修改记录，状态变成“已通过”，然后再切图|

选择“补充漏标目标”只会生成说明，**不会自动补框**。需要先在画布真正修改。正常情况不必写文字；补充说明是选填的。“核对无误，保留现有框”只用于完全没改框的图片，不要与修改选项同时勾选。

看不清、目标性质不确定时，可以选择相关处理项，或仅填写简短说明，例如“右侧薄雾与烟雾不易区分，待看原图”，然后 **保存草稿**。这不要求新增仲裁环节，也不能把拿不准的图直接通过。切图前保存重要修改，刷新/关闭浏览器不保证保留未保存画布。

## 怎么判断和画框

- **fire：可见明火。** 围住可见火焰轮廓；仅有橙色灯光、反射、发光屏幕或无法确认的亮点，不直接标为fire。多个空间分离的火焰团分别画框；连续同一团火焰用一个紧凑框。
- **smoke：可辨认的烟雾。** 重点观察烟从哪里出现、可见烟羽或扩散区域。烟边界很软时，以能辨认的可见范围为准，避免把整片背景一起圈进去。静态图无法仅凭颜色区分蒸汽、雾与烟时保存草稿核查，不凭想象补框。
- 火焰上方同时有烟时，可以分别画fire与smoke，两种类别的框允许相交。不要把“燃烧物体”整体当成火焰，也不要用一个fire框同时代替烟雾。
- 图片没有任何框，也必须检查整张图。只有确实没有fire和smoke时，才删除全部误框，并勾选 **“我已检查整张图，确认没有 fire 或 smoke”**。模型空输出不等于正常场景。

## 如何利用旧候选省事

页面提示“原方案含该类候选”时，可在“预标注版本”选较早的Tiny候选，展开模型记录确认版本，点击“采用所选预标注”，再修正。这会替换当前未保存画布，因此先保存重要修改。已保存的历史不会被覆盖。

旧候选也可能有误框，不能整张照抄。例如 **Q103（ID开头6e22b4efa48d）**：清单生成时增强候选为0框，旧候选共2框，包含fire和smoke。使用旧候选后仍要看原图，核对烟雾范围、判断fire框是否误检；不能因为旧版本有框就直接通过。若已经有人工版本，先检查它是否正确，无须再次采用模型结果。

不要求逐图查看A/B，也不需要重新提交独立任务。必要时回Quality查看已完成任务的原始标注作为参考，最终保存仍以原图检查为依据。

## 做完后怎么确认

1. 回到优先范围，取消“只看尚未通过”，查看“已通过/尚未通过”数量及26幅状态表。
2. 本轮目标是26幅全部有正确的已通过人工版本；尚未通过的草稿继续保留为待处理，不能拿草稿当训练标签。
3. 抽看几张修改记录，确认新增/删除/修改与实际操作一致；需要留档可下载此图完整修改记录。
4. 这些26幅通过，只代表这份优先清单完成。其余未通过图片仍须正常人工复核；生成完整YOLO训练包前，所选划分的全部图片必须通过。

如要补做人工节省工时估算，从开始实际看图、改框时计时，离开/休息暂停，记录图片数和有效分钟数。之前没有计时的复核不能倒填；页面停留时长含空闲，不等于有效人工工时。

## 清单来源与复现

清单只保存编号、图像ID/哈希、需检查类别、来源候选版本等线索，没有A/B框坐标。生成前检查A/B均已全部提交、Q编号对应原任务、A/B均含指定类别、指定批次确实缺少该类；不向数据库写入任何标注。清单冻结后不因模型重跑或保存人工版本改变成员。若后来新增了候选，页面会提示旧清单依据，不断言新版本仍漏检。

在保留本机原始诊断文件和完整数据目录的环境中，可复现生成：

```powershell
.\.venv\Scripts\python.exe scripts\prepare_priority_review.py --source-report artifacts\prelabel_optimization_20261027\batch\known_human_reference_priorities.json --task-id quality_6146eb5a5ab24f5ebc6961d07e392ad2 --batch-id enhanced_base_20261027
```

相同输入可重复运行；已有不同清单时会停止，避免悄悄替换。实际图像、数据库、清单和模型权重均保留本机，不提交到代码仓库。
